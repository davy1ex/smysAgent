# ADR-0011: Внутренний контракт событий хода агента

- Статус: Accepted
- Дата: 2026-10-30
- Утвердил: владелец проекта в чате

## Контекст

Runtime уже выполняет несколько вызовов модели и может вызывать инструмент, а отдельный Web путь передаёт текстовые чанки. Application сохраняет только сообщения и не предоставляет общий типизированный callback для наблюдения за ходом. Для live UI и будущего сохранения trajectory нужен один внутренний контракт, который не зависит от HTTP, React или provider API.

## Варианты

1. Добавлять отдельные поля для reasoning и отдельные HTTP/SSE контракты для инструментов и streaming — просто начать, но каждый следующий шаг потребует менять предыдущий транспорт.
2. Ввести общий `AgentEvent` callback сейчас, оставить транспортацию и хранение отдельными последующими этапами — сохраняет границы Core/Application и позволяет использовать одинаковый порядок событий в существующем Promise и streaming runtime.

## Решение

- Core экспортирует единый discriminated union `AgentEvent` и сообщает runtime-события через необязательный `onEvent` callback.
- Для каждого вызова модели Runtime отправляет `model.started` и, если ответ валиден, `model.completed`; `callIndex` начинается с 1. Непустой provider reasoning передаётся отдельным `reasoning.completed` для своего вызова модели. `AgentTurnResult.reasoning` сохраняет прежнее агрегированное значение.
- После ответа модели с tool call Runtime отправляет `tool.requested` с `callId`, именем и аргументами. `tool.started` отправляется только после проверки аргументов и `allow`; `tool.completed` содержит результат только после успешного исполнения.
- Streaming Runtime использует тот же callback для `assistant.delta`, сохраняя существующий `onTextDelta`.
- Application отправляет `turn.started` после записи user message, `turn.completed` после записи assistant message и `turn.failed` при ошибке. Ошибка хода продолжает выбрасываться; код события использует безопасный код ошибки.
- События не сохраняются в store. На момент утверждения этого ADR они не передавались через Web HTTP API; транспортировка событий через SSE и добавление reasoning к `turn.completed` утверждены позднее в ADR-0012. Store v2 и базовый JSON/CLI контракты остаются прежними.

## Последствия

- Application callers могут наблюдать последовательность model, reasoning, tool и turn events без изменения `Promise` результата `runAgentTurn`.
- Если provider не вернул reasoning, соответствующее событие не отправляется; при ошибке provider `model.completed` не отправляется.
- `tool.requested` может завершиться отказом и сам по себе не означает исполнения.
- `onEvent` вызывается последовательно и ожидается Runtime/Application; ошибка обработчика прерывает незавершённый ход. Ошибка доставки `turn.failed` не подменяет исходную ошибку.
- Web transport, политика доступности tools и потоковый provider протокол позднее сведены в ADR-0012. Сохранённая trajectory остаётся отдельным будущим решением.
- Откат удаляет callback и типы событий; данные хранилища мигрировать не требуется.
