# ADR-0007: Статический React web-макет

- Статус: Accepted
- Дата: 2026-10-29
- Утвердил: владелец проекта в чате

## Контекст

Нужно оценить удобство интерфейса чата до подключения backend. В макете должны быть тестовые сообщения, reasoning, вызов инструмента и раскрываемые детали. Core и Application остаются без изменений.

## Варианты

1. Добавить React-приложение в корневой пакет. Это смешало бы web-инструменты с текущим CLI и его TypeScript-конфигурацией.
2. Создать отдельный пакет в `src/apps/web` на React и Vite. У него будут собственные зависимости, команды и TSX-конфигурация.
3. Использовать только HTML и CSS. Это не удовлетворяет требованию React.

## Решение

- Создать изолированный React/Vite пакет в `src/apps/web`.
- Хранить демонстрационные данные и модель отображения внутри пакета; они не являются контрактами Core или Application.
- Оставить макет автономным и статическим. Единственное интерактивное поведение в этом срезе — раскрытие reasoning и деталей вызова инструмента.
- Не менять корневые runtime-зависимости, Core, Application, формат хранения и application API.

## Последствия

- Пакет устанавливается и запускается отдельно через npm.
- Production-сборка остаётся статическими файлами; backend и сетевые сервисы не требуются.
- UI-фикстуры могут разойтись с будущими контрактами. При подключении настоящих данных потребуется отдельно спроектировать адаптер отображения и определить доступность reasoning/tool details.
- Откат: удалить `src/apps/web` и этот ADR, затем вернуть документацию к состоянию без статического preview.
