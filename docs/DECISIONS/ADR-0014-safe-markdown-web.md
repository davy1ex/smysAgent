# ADR-0014: Безопасный Markdown в Web ответах

- Статус: Accepted
- Дата: 2026-11-02
- Утвердил: владелец проекта в чате

## Контекст

Web сейчас вставляет assistant text как обычный текстовый узел, поэтому Markdown в ответах отображается как исходные символы. Ответ модели является недоверенным вводом; HTML и небезопасные ссылки нельзя исполнять в браузере.

## Варианты

1. Написать собственный Markdown parser/renderer — избегает зависимости, но создаёт неполную и трудно проверяемую реализацию формата.
2. Использовать `react-markdown` с `remark-gfm` и безопасными настройками по умолчанию — даёт CommonMark/GFM через React elements без ручной вставки HTML; выбран владельцем проекта.

## Решение

- Web UI использует `react-markdown` и `remark-gfm` для streaming draft и финальных assistant сообщений.
- Raw HTML не преобразуется в DOM: не подключать `rehype-raw`, не использовать `dangerouslySetInnerHTML` и не переопределять URL transform небезопасным способом.
- Ссылки рендерятся через стандартную URL validation библиотеки; открытые пользовательские схемы не разрешаются дополнительно.
- User messages остаются plain text. Markdown пакет и его стиль принадлежат только Web UI; provider/Core/API/store контракты не меняются.

## Последствия

- Web bundle включает две runtime зависимости.
- Незавершённый streaming Markdown повторно рендерится по мере фактических `assistant.delta`; искусственная анимация не используется.
- Проверки должны покрывать CommonMark/GFM разметку, HTML в ответе модели и небезопасные URL protocols.
- Откат возвращает assistant content к plain text и удаляет обе Web зависимости; формат хранения и история не меняются.
