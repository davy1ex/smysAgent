# ADR-0009: Локальный HTTP host для Web

- Статус: Accepted
- Дата: 2026-10-29
- Утвердил: владелец проекта в чате

## Контекст

Браузерный React-клиент не может напрямую вызывать Node Application API. Web preview из ADR-0007 и оболочка из ADR-0008 должны стать клиентом настоящих сессий, не перенося agent loop в UI и не создавая отдельную бизнес-логику.

## Варианты

1. Импортировать Application/Core из React. Это невозможно в браузерном runtime и нарушает границы модулей.
2. Добавить небольшой Node HTTP host поверх Application API и проксировать локальные `/api` запросы через Vite. Это вводит только нужный транспорт и не добавляет runtime-зависимостей.
3. Встроить API middleware в Vite. Такой host зависел бы от dev-инструмента и не являлся бы самостоятельным приложенческим входом.

## Решение

- Создать Node host в `src/apps/web-host`; он вызывает существующие Application use cases, а не реализует бизнес-логику.
- Host по умолчанию слушает `127.0.0.1:3001`. Vite проксирует `/api` на этот адрес; отдельный CORS-контракт не вводится.
- Реализовать чтение списка сессий и истории, создание сессии и отправку сообщения с выполнением полного agent turn.
- Вычислять заголовок по первому пользовательскому сообщению и `updatedAt` по последнему сообщению. Формат JSON-хранилища не менять.
- Выбирать provider через `SMYS_PROVIDER=fake|lm-studio`; Fake используется по умолчанию. LM Studio получает модель и endpoint из переменных окружения, токен остаётся только в host.
- Сериализовать POST-запросы одним процессом host. CLI и другие процессы не должны одновременно записывать тот же JSON store.
- Ввести `runId` на уровне application turn и HTTP-ответа. События runtime и trace пока не сохраняются; UI показывает только реальные сообщения и временный статус текущего хода.
- Сохранить React/Vite пакет и оболочку из ADR-0007/0008, отменив ограничения на демонстрационные данные и read-only composer.

## Последствия

- CLI продолжает обращаться к тем же use cases напрямую; Web обращается к ним через transport host.
- HTTP API локальный и не имеет аутентификации. Host не слушает сетевые интерфейсы.
- Если provider завершился ошибкой после сохранения user message, запись остаётся в истории без ответа ассистента; UI показывает ошибку хода.
- Одновременные записи разных процессов по-прежнему не защищены JSON adapter. SQLite, события, сохранённая trajectory, streaming, проекты и публикация host остаются отдельными решениями.
- Откат: вернуть Web к локальным фикстурам, удалить `src/apps/web-host` и ADR-0009, убрать host script/API proxy и вернуть контрактную документацию к состоянию до этого host.
