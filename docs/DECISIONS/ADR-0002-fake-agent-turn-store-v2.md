# ADR-0002: Один ход через fake provider и store v2

- Статус: Accepted
- Дата: 2026-10-28
- Утвердил: владелец проекта в чате

## Контекст

Первый CLI-срез сохранял только сообщения пользователя. Для проверки сквозного пути нужен один детерминированный ход, сохранённый ответ ассистента и чтение полной истории новым процессом. Изменение формата затрагивает уже существующие файлы `store.json` версии 1.

## Варианты

1. Оставить fake provider только в тестах: CLI-процессный сценарий не проверит композицию приложения.
2. Использовать fake provider по умолчанию: команда может выглядеть как обычный запуск модели, хотя ответа реальной модели не будет.
3. Добавить отдельную команду хода с обязательным `--provider fake`: поведение видно в CLI и легко проверяется между процессами.

Для миграции рассматривались преобразование при открытии, преобразование при первой записи и отдельная команда миграции.

## Решение

- Добавить `agent run --provider fake --session-id <id> --text <text>`. Не менять семантику `message send`.
- Использовать минимальный синхронный текстовый порт provider; один вызов возвращает детерминированный текст. В этом срезе нет живой модели, сети, ключей и инструментов.
- Сохранять пользовательское сообщение до вызова provider. При ошибке provider пользовательское сообщение остаётся в истории без ответа; ошибка использует `INTERNAL_ERROR` и код выхода `1`.
- Перейти на `store.json` версии 2 с текстовыми сообщениями ролей `user` и `assistant`; sequence общий для сессии.
- Читать валидный v1 без записи на диск. При первой мутации сохранить точные исходные bytes в `store.json.v1.bak`, затем атомарно записать v2. Существующий backup использовать только при точном совпадении с v1.
- Неизвестный или повреждённый формат отклонять без изменения исходного файла и без автоматического сброса. Ошибка хранилища использует код выхода `4`.
- Сохранять при миграции все существующие поля сессий, сообщений и корневого документа. Конкурентная запись несколькими процессами не входит в этот срез.

## Последствия

- Application API и CLI проверяют детерминированный путь через fake provider; второй процесс может прочитать пользовательское сообщение и ответ ассистента в правильном порядке.
- Первый write существующего хранилища v1 создаёт v2 и резервную копию. Старые версии программы, понимающие только v1, не читают основной файл v2; откат выполняется восстановлением `store.json.v1.bak`.
- Реальный provider, retry, streaming, инструменты и транзакционность всего хода остаются отдельными решениями.
