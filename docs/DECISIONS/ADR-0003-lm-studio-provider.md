# ADR-0003: LM Studio через OpenAI-compatible Chat Completions

- Статус: Accepted
- Дата: 2026-10-28
- Утвердил: владелец проекта в чате

## Контекст

Нужен первый реальный model provider для существующего `TextGenerationProvider`, не меняя application API, runtime-порт и формат истории. `agent run` должен делать ровно один обычный текстовый запрос, сохранять ответ существующим application API и оставлять fake provider детерминированным и явно выбранным.

## Варианты

1. Native LM Studio `POST /api/v1/chat`: рекомендованный LM Studio API с stateful-чатом, но для продолжения чата приложение должно было бы сохранять и связывать удалённые `response_id` с локальной сессией.
2. OpenAI-compatible `POST /v1/chat/completions`: передаёт полную историю в каждом запросе, включая предыдущие assistant-сообщения, и не требует состояния на стороне LM Studio.
3. Добавить SDK или другую зависимость: это не нужно для одного синхронного HTTP-запроса в поддерживаемом Node.js runtime.

## Решение

- Добавить `LmStudioProvider`, реализующий существующий `TextGenerationProvider`; использовать встроенный `fetch` без новой зависимости.
- Оставить выбор provider явным: `--provider fake` или `--provider lm-studio`. Не добавлять неявный provider по умолчанию или fallback.
- Для LM Studio требовать `--model <model-id>`. Принимать полный URL endpoint через `--endpoint`, затем `LM_STUDIO_ENDPOINT`; default — `http://localhost:1234/v1/chat/completions`.
- При наличии `LM_API_TOKEN` передавать его только в `Authorization: Bearer`. Не сохранять и не выводить значение токена.
- Отправлять один запрос с полями `model`, `messages` (вся история в порядке сообщений, только `role` и текстовый `content`) и `stream: false`. Инструменты не отправлять. Читать финальный текст из `choices[0].message.content`, а при наличии нормализовать `choices[0].message.reasoning_content` как reasoning текущего ответа.
- Преобразовывать ошибки соединения, HTTP-ошибки, невалидный JSON/ответ и отсутствующий или пустой текст в безопасную ошибку provider. CLI отображает её через существующий `INTERNAL_ERROR`, код выхода `1`; тело ответа не выводится. Не повторять запрос и не переключать provider.
- При ошибке provider сохранить поведение application API: пользовательское сообщение уже записано, ответ ассистента не добавляется.
- Проверять adapter детерминированными тестами с подменённым `fetch`, а CLI-процессный путь — с локальной HTTP-заглушкой. Живой smoke-запрос не включать в автоматические проверки.

## Последствия

- Runtime и application API остаются независимыми от LM Studio и формата сетевого протокола; adapter находится в `packages/providers`.
- История продолжает храниться только в собственном JSON store; схема хранилища и миграция не меняются.
- Каждый вызов передаёт endpoint всю историю текущей сессии. Пользователь отвечает за выбранный endpoint; если настроен `LM_API_TOKEN`, его получает этот endpoint.
- Reasoning возвращается через внутренний provider/runtime контракт для текущего вывода, но не сохраняется в истории сессии.
- Сбой LM Studio виден скриптам через существующий стабильный CLI error contract. Автоматических retry и fallback нет.
